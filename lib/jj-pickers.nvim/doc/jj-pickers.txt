==============================================================================
1. REQUIREMENTS                                       *jj-pickers-requirements*

  - Neovim >= 0.10   (vim.system, vim.fs.root, vim.uv)
  - jj  >= 0.30      (templates: path, status_char, current_working_copy,
                      local_bookmarks)
  - folke/snacks.nvim with `picker` enabled

Run |:checkhealth| jj-pickers to verify all of the above plus the current repo.

==============================================================================
2. SETUP                                                     *jj-pickers-setup*

>lua
    require('jj-pickers').setup {}
<
setup() is optional except to change |jj-pickers-config| or to have the plugin
install its own keymaps. Both pickers are registered as snacks sources, so
after setup() all of these work: >lua
    require('jj-pickers').changes()
    Snacks.picker.jj_changes()
<
and `Snacks.picker.resume()` can resume either one.

==============================================================================
3. COMMANDS                                               *jj-pickers-commands*

:JjChanges [revision]                                            *:JjChanges*
    Files changed in {revision} (default `@`).

:JjRevisions [revset]                                          *:JjRevisions*
    Revisions matching {revset} (default `trunk()..@`).

==============================================================================
4. PICKERS                                                 *jj-pickers-pickers*

jj_changes                                            *jj-pickers-jj_changes*
    One row per file changed in a revision, with a jj status glyph and the
    basename tinted by status. The preview is that file's diff at
    `context` lines of surrounding code, with the cursor dropped on the first
    changed line and centred.

        <CR>    open the file at the first hunk
        <c-s>   open in a split      (also <c-v> vsplit, <c-t> tab)
        <c-o>   switch to the revisions picker
        <c-y>   yank the absolute path

    A file the revision deleted has nothing on disk; <CR> reports that rather
    than opening an empty buffer.

jj_revisions                                        *jj-pickers-jj_revisions*
    One row per revision, newest first, in jj's topological order. The node
    column uses jj's own vocabulary: `@` working copy, `◆` immutable, `○`
    mutable. A conflicted revision shows a conflict glyph; otherwise a
    bookmarked one shows a bookmark glyph. The preview is `jj show --git`.

        <CR>    jj edit, or jj new when `on_revision = 'new'`
        <c-e>   jj edit  — @ becomes this revision; later saves amend it in
                           place and rebase descendants
        <a-n>   jj new   — empty child; works on immutable revisions
        <c-l>   drill into the files changed in this revision
        <c-y>   yank the change id
        <a-a>   lift the `limit` cap and re-run

    jj edit prompts when buffers are unsaved. jj snapshots the working copy
    from disk, so an unwritten buffer still belongs to the revision you are
    leaving; saving it after the switch would land that work in a different
    change.

==============================================================================
5. CONFIGURATION                                            *jj-pickers-config*

>lua
    require('jj-pickers').setup {
      revset = 'trunk()..@',
      limit = 20,
      revision = '@',
      on_revision = 'edit',   -- or 'new'
      context = 12,
      keys = nil,             -- { changes = '<leader>jj', revisions = '<leader>jl' }
    }
<
`keys` is opt-in. If your plugin manager already declares the mappings (for
lazy.nvim, `keys =` also drives lazy-loading) leave it nil; :JjChanges and
:JjRevisions always exist regardless.

Appearance and layout are not configured here. Both pickers are ordinary
snacks sources, so use snacks' own config: >lua
    { 'folke/snacks.nvim', opts = { picker = { sources = {
        jj_revisions = { layout = { preset = 'vertical' } },
    } } } }
<
If `trunk()` cannot resolve — a repo with no remote bookmarks — jj falls back
to `root()`, and `trunk()..@` would then mean the entire history. jj-pickers
detects this, warns, and uses `::@` instead.

==============================================================================
6. EVENTS                                                   *jj-pickers-events*

User JjPickersWorkingCopy                            *JjPickersWorkingCopy*
    Fired after a successful jj edit / jj new, once the working copy on disk
    has changed. `data` is `{ root, change_id, verb }`. jj-pickers already
    issues |:checktime|; use this to refresh anything else. >lua
        vim.api.nvim_create_autocmd('User', {
          pattern = 'JjPickersWorkingCopy',
          callback = function() require('gitsigns').refresh() end,
        })
<
